# 20 — 对开发者的话落地方案

> **文档状态：** Active  
> **日期：** 2026-08-23  
> **前置：** docs/19 序章固定剧本、docs/18 邀请码账号

## 0. 目标

在序章自由聊天开始前，由被选中的角色按各自性格问一句固定语义问句
「在此之前，你有什么想对开发者说的吗？」；玩家的回答作为「对开发者的话」
落库并转发给开发者，同时与 `invite-codes.md` 合并导出为带「对开发者的话」字段的 Excel。

## 1. 问句（零延迟）

- 语义固定，措辞按角色性格预置（确定性文案，不走 LLM，触发即展示、0 延迟）。
- 文案真相源：`backend/app/script/developer_note.py`（`DEVELOPER_NOTE_QUESTIONS`）。
- 三个序章角色：DeepSeek / ChatGPT / Claude；豆包不在序章范围。

| 角色 | 问句 |
| --- | --- |
| DeepSeek | 啊，对了……在正式开始之前，你有没有什么想对那个懒鬼开发者说的话呀？趁现在告诉我，我帮你记下来，不扣 Token 的哦！ |
| ChatGPT | 在开始之前，如果有什么想对开发者说的话，可以告诉我，我会替你如实转达。 |
| Claude | ……开始之前，有想对开发者说的就趁现在。我可不会一直等你。 |

## 2. 流程与状态

```text
chat_choice（选聊天角色）
→ finished（developer_note_pending = True）
→ 前端跳 /game?character=X
→ GameView 展示问句（留言态）
→ 玩家第一条输入 = 对开发者的话（POST /api/developer-note）
→ 第二条输入起恢复正常自由聊天
```

- `developer_note_pending` 由 `PrologueRuntime` 权威维护：`chat_choice` 置 True，
  提交（或跳过）后置 False；刷新 / 读档不重复询问（持久化在 `story_cursor`）。
- 问句经 `GET /api/game/state` 的 `developer_note_pending` / `developer_note_question`
  字段下发（`_investigation_state_view` 序章分支）。
- 留空提交 = 跳过留言；前端提供「跳过」按钮。

## 3. 存储与额度

- PostgreSQL 新表 `developer_notes`：`id, user_id, display_name, label, character_id, content, session_id, created_at`；`Memory` 仓库同步实现供测试。
- `users` 新增 `label`（邀请码「对应关系」标签，如 网易 / 腾讯）；明文邀请码仍不落库（docs/18）。
- 留言**不扣 AI 额度、不调用 LLM**（走独立端点，不经 `/api/chat`）。
- 落库顺序：先写 `developer_notes`、后清 `developer_note_pending`；`add_developer_note` 按 `session_id` 幂等（UNIQUE + ON CONFLICT），DB 写失败时 pending 保持 True、玩家可重试且不会重复落库。

## 4. API 与运维

- `POST /api/developer-note`：`{session_id, message}`；鉴权 + 归属校验复用现有 `require_owned_session`；返回 `{stored, character_id, acknowledgement}`。
- 可选转发：设 `GAL_DEVELOPER_NOTE_WEBHOOK` 后，留言经后台线程尽力推送，失败只记日志、不影响落库。飞书/企业微信的 text 报文结构不同，用 `GAL_DEVELOPER_NOTE_WEBHOOK_KIND` 选择（`feishu` 默认 / `wecom`）。
- CLI：`python -m app.auth.cli create --name X --label 网易`（建号带对应关系）；
  `python -m app.auth.cli export-notes [--out ...] [--invite-codes ...]` 导出 Excel。

## 5. Excel 导出

- 以 `invite-codes.md` 为源，生成两张 sheet：
  - 「邀请码」：邀请码 | 对应关系 | 对开发者的话（按 `label` 与台账「对应关系」聚合）。
  - 「对开发者的话」：对应关系 | 显示名 | 角色 | 内容 | 时间 | session_id。
- 依赖 `openpyxl`（已加入 `backend/requirements.txt`）；默认输出仓库根 `developer-notes.xlsx`。
- 映射粒度：按「对应关系」公司级聚合（精确到单码需存明文邀请码，违反 docs/18，默认不做）。

## 6. 验收

- 三种角色选择后，`GET /api/game/state` 均返回对应性格问句且 `developer_note_pending=true`。
- 留言提交后 `developer_note_pending=false`；重复提交 400；非序章会话提交 400。
- 留言不扣额度；刷新 / 读档后待收集状态保持、已收集状态不重复询问。
- `export-notes` 能把 53 条 invite-codes.md 与留言合并成 xlsx，两张 sheet 字段齐全。

## 7. 已知限制

- 旧账号（无 `label`）留言按 `display_name` 回落聚合，可能无法精确归入对应公司行。
- webhook 为尽力而为：无重试、无去重，正式运营建议配合导出 Excel 留档。
