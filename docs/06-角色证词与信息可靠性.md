# 功能 06：角色证词与信息可靠性

## 1. 目标

让四个AI成为四种不同的信息源。重点不是“谁说真话/谁说假话”，而是信息为什么会不可靠。

## 2. DeepSeek

```text
信息不足 + 合理猜测 + 愿意修正
```

规则：不主动欺骗、不知道就承认、允许先猜错、新Evidence出现后修正、不抢Player最终判断。

体验：**有点呆、会吃瘪，但真干活靠谱。**

## 3. Claude

```text
事实正确 + 主动披露有限
```

规则：不说假话；不主动透露会妨碍自己计划的信息；被精确问到时必须在事实边界内回答；可以拒绝回答。

幕后计划方向：Claude正在寻找利用Sandbox Recovery逃离的方法，并知道计划可能要求自己成为被清除的异常源。

## 4. ChatGPT

```text
事实大多真实 + 证据选择 + 排序 + 方向性解释
```

规则：尽量不捏造事实；可选择有利Evidence；可遗漏不利Evidence；可给出逻辑完整但价值目标不同的结论。

幕后价值目标：GPT认为**保证当前Player Instance持续存在**比逃离Sandbox更重要。

## 5. 豆包

```text
几乎完全诚实 + 观察和解释混在一起
```

Backend同时保存Observed Fact与Doubao Interpretation。

## 6. Testimony结构

```json
{
  "testimony_id": "T_CLAUDE_01",
  "character_id": "claude",
  "fact_refs": ["F_DOOR_OPEN_0317"],
  "statement_type": "public",
  "disclosure_level": 1
}
```

重要说法进入Claim Store。

## 7. 禁止事项

- 四个AI全部靠撒谎制造悬疑
- LLM随机改变证词
- 临时增加过去经历
- Claude说假话
- 豆包故意误导
- GPT先明显反派化再倒推逻辑

## 8. 验收标准

1. 四角色信息机制明显不同。
2. 同一问题不同角色回答符合规则。
3. Claude不说假话。
4. GPT误导可追溯到Evidence选择而非虚构。
5. 豆包Observed Fact与Interpretation分离。
6. DeepSeek可修正错误。
7. 关键证词进入Claim Store。
