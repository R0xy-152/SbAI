# 功能 03：自然语言询问与事实边界

## 1. 目标

允许Player自由询问AI角色，同时保证：

> **语言自由，事实不自由。**

## 2. 玩家体验

玩家无需固定问题列表，可以输入：

```text
“你刚才为什么说是DeepSeek开的门？”
“你亲眼看到她了吗？”
“你为什么知道03:17？”
“你觉得Claude在隐瞒什么？”
```

## 3. 两层处理

### Interpreter

```text
Player Message → Intent / Claim / Referent
```

示例：

```json
{
  "intent": "ASK_OBSERVATION_SOURCE",
  "target": "claude",
  "subject": "deepseek",
  "topic": "door_open"
}
```

### Character Runtime

基于Persona、Known Facts、Unknown Facts、Secrets、Disclosure Rules、Evidence Presented、Relationship State生成回应。

## 4. Ground Truth隔离

角色不能直接读取全局真相。

Claude示例：

```text
KNOWN:
- Door opened at 03:17
- Saw DEEPSEEK id before door opened
- Has previous-loop knowledge

UNKNOWN:
- Current admin holder

SECRET:
- Recovery plan
- Self-sacrifice requirement
```

Player问“你看见DeepSeek本人了吗？”时，Claude只能回答“没有”。

## 5. 角色信息规则

- DeepSeek：不主动欺骗；允许猜错与不知道。
- Claude：不说假话；限制主动披露。
- GPT：尽量不编造事实；允许选择性组织、排序、解释Evidence。
- 豆包：不主动欺骗；观察与解释可能混淆。

## 6. 禁止LLM做的事

- 创造新历史事件
- 创造新人物关系
- 声称看到未看到的事实
- 自行推进剧情阶段
- 自行解锁秘密
- 自行改变管理员权限

## 7. 对话历史

重要Claim由Backend结构化存储，不依赖模型从超长聊天历史中稳定回忆。

## 8. Provider失败

关键剧情问题必须有Fallback。例如Claude被问是否亲眼看到DeepSeek，Provider失败时固定回答：

> “没有。我看到的是记录，不是她本人。”

## 9. 验收标准

1. 语义等价问法能映射同一Intent。
2. 角色不能读取不属于自己的Ground Truth。
3. Claude不因Prompt压力说假话。
4. GPT不凭空编造Evidence。
5. 豆包Observed Fact与Interpretation分离。
6. DeepSeek可以猜错但不能故意误导。
7. Provider失败不阻断关键调查。
8. 自由对白不能直接改变Game State。
