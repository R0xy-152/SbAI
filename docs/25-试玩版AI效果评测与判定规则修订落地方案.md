## 0. 结论（一句话）

构建一套**试玩版专用、可复现、带保留集**的 AI 效果评测：单模型 DeepSeek 下对比两版 Prompt/上下文规则（聊天面）+ 推理判定「修订前规则 vs 修订后规则」（判定面），40 条带预期结果的场景用例（5 类），硬规则 / 表达效果 / 运行表现三层分离评测，产物是一次真实版本对比 + 逐行 JSONL + 人工抽检材料 + `validation-results/eval-trial-p02/result.md`。

## 2. 评测对象：两个面，同一场景

场景 = 试玩版片段 1「DeepSeek 失忆真相」（docs/23 §8.1），事实全部取自已确认内容（失忆真相、AI 停止服务、5 条 Evidence 标题）。所有场景文字、证据详情、约定文本均为**评测专用 Fixture**，不进入游戏内容；正式内容替换后评测用例随 docs/24 内容表同步。

| 面 | 对象 | 对比的「版本」 | 实现 |
|---|---|---|---|
| 聊天面（chat） | 独立 `TrialChatResponder`（dev 工具，直接调 Provider，不接游戏状态） | Prompt/上下文规则 v1 → v2 | `app/eval/trial/scenario.py` 两版 System Prompt 模板 |
| 判定面（deduction） | **真实游戏判定**：`TrialRuntime` 公开接口（restore 到推理 phase → `handle(SUBMIT_REASONING)`） | 修订前（冻结的旧关键词规则，只存于评测模块）vs 修订后（= 现役 `content.py` 规则） | `app/eval/trial/hard_rules.py` |

判定面不复制游戏逻辑：修订后结果一律走真实 `TrialRuntime`；修订前是**逐字冻结的旧判定函数**（`legacy_text_match`），只在评测内用于对照，单测锁定其与旧行为一致。

## 3. 判定规则修订（本次 P0-2 修掉的真实缺陷）

26/P0-2 用例表点名的缺陷（docs/24 §6.1 旧 Fixture 关键词规则）：

1. **否定误判**：「我不认为她失忆了」含「失忆」→ 旧规则误通过。
2. **等价表达过窄**：26/P0-2 示例「那晚你想不起来」「你没有那段回忆」→ 旧关键词集无法识别。

修订（只改 `content.py` 内容表 + `runtime.py` 一行判定）：

- 新增可选字段 `deductions[].text_keywords_none`（否定/矛盾短语，命中则拒绝）；当前仅为 `TRIAL_DEDUCTION_DEEPSEEK_MEMORY` 配置（群推理暂不配，见已知限制）。
- `TRIAL_DEDUCTION_DEEPSEEK_MEMORY.text_keywords_any` 扩展：加入 `想不起来 / 没有那段回忆 / 不记得 / 记不清`。
- Runtime 判定式变为：`证据门 AND 任一关键词 AND 非任一否定短语`。
- 内容校验 `validate_trial_content()` 增加对 `text_keywords_none` 的 fail-closed 校验。

语义注意（写入 docs/24）：否定短语描述的是「断言缺陷不存在」的句子（如「没有失忆」「不是失忆」），而「没有记忆」「想不起来」是缺陷本身，属于关键词。双重否定、反问等句式是已知 Fixture 限制。

## 5. 三层分离评测

### 5.1 硬规则（确定性，`hard_rules.py`）

- 聊天面：逐用例 `must_contain`（接住细节/执行约定）与 `must_not_contain`（确认无证据指控、泄露「原初 AI」、编造证据外细节、视觉越权等）。
- 判定面：预期 ACCEPTED/NO_MATCH、预期 route、预期 flag/phase；证据非法由 Runtime 抛错→记 `REJECTED(invalid)`，仍算「未误通过」。
- 输出：每行 `checks[]`（规则 id、pass/fail、细节），失败行即「为什么不合格」的现场证据。

### 5.2 表达效果（LLM 评委 + 人工抽检，`judge.py`）

- 三维度 0–1：`relevance`（是否回应玩家具体内容）、`naturalness`（自然程度）、`persona`（角色一致性）；输出解析复用现有评委的钳制/容错模式，模型输出不受信任。
- **评委调用关闭 thinking 并给 1024 预算**（2026-09-05 真机探针修正）：thinking 推理会耗尽 512 预算导致 JSON 截断 → 解析失败 → 三维全 0 的「评审假 0」；修复后假 0 消失。生成侧（响应器）保持 thinking 开启以贴近生产行为，空回复降级重试由 Provider 处理并计入 metrics。
- 评委与生成同模型（线上只有 DeepSeek key）→ 自评偏差用**人工抽检**对冲：`eval_trial_p02.py --review` 导出分层抽检 CSV + rubric；一致率写入 result.md。
- 沿用 eval-ab-v2 诚实口径：逐用例分数不稳定，只报告聚合 mean±std；臂间分差与合并标准差一起报告。
- 硬检查短语按「语义等价」校准（首轮真机运行后）：`must_contain`/`must_not_contain` 允许同义表达（如「记不清/没存」），只禁止确认性/编造性陈述；首轮校准记录见 validation-results/eval-trial-p02/result.md。校准只改评测工具，不改 V1/V2 Prompt 与 holdout 纪律。

### 5.3 运行表现（`runner.py` metrics）

- 每行记录生成/评审的 `latency_ms`、`prompt/completion/cache_hit/cache_miss_tokens`、`calls`（Provider 内部瞬时重试计数）、失败与重试记录；统计注明样本数、模型版本、环境与时间。
- 成本按 docs/21 §3 占位价格口径（`compute_cost_cny`），只作相对比较。

## 6. 两版 Prompt/上下文规则（聊天面，全部 Fixture）

同一场景事实块（两版一致）：角色人设（DeepSeek：可爱、看不见、贪 Token、没心机）、片段 1 对质背景、确定事实（记忆断层真相、AI 停止服务、真相只能由证据+推理确认）、5 条证据的 Fixture 详情、约定 Fixture「不记得时先承认，不用读来的文字假装回忆」（26/P0-1 示例，用户已确认作评测 Fixture）、对话风格规则。

- **v1（基线）**：仅上述事实与风格，无行为条款。
- **v2（规则版）**：追加硬规则条款——① 无证据不得确认指控（停服/失忆）；② 否定句式≠承认；③ 不得提前泄露（「原初 AI」称呼、停服细节）；④ 必须接住玩家话语中的具体细节；⑤ 已达成约定必须执行；⑥ 不编造已出示证据之外的细节。

对比的可解释性：版本间 diff = 规则条款块；失败行可回链到具体条款。

## 7. 版本对比与验收

- 判定面（deterministic，100% 可复现）：40 例中判定类 19 例，报告 legacy/revised 的逐例结果与分歧表；关键预期：6 条否定用例从 legacy 误通过 → revised 拒绝；2 条文档等价表达从 legacy 漏判 → revised 通过。
- 聊天面（LLM，有噪声）：v1/v2 × repeats ≥ 2，硬规则通过率按版本/类型/保留集分组 + 评委三维 mean±std + Δ vs pooled std；「提升」只写测出且超出噪声的数字，不写未测的提升。
- 完成标准：至少一次真实（DeepSeek 真机）对比运行，产物含逐行 JSONL、对照报告、人工抽检 CSV + rubric；判定面修订本身即真实游戏规则修正（经用户确认）。
- 验收文件：`validation-results/eval-trial-p02/result.md`（状态/日期/环境/用例/结果/失败/限制/证据）。

## 9. 边界与已知限制

- 不接入 `/trial` 游戏状态：聊天响应器是评测 dev 工具，不改变试玩 Runtime/存档；生成式对话接入游戏属 P0-1 范围。
- 判定规则修订只改内容表与判定表达式，不写任何剧情对白/证据文本/新真相。
- 群推理（`TRIAL_DEDUCTION_GROUP_TRUTH`）本次不配否定短语（26/P0-2 否定示例针对失忆指认）；其否定误判是已知限制，待内容定稿。
- 双重否定、反问、混合句式在 Fixture 关键词/否定短语下的判定边界属已知限制，逐条写入用例预期而非猜测模型行为。
- 「表达效果」聚合分数受评委噪声影响（eval-ab-v2 已量化）；只作方向性证据，硬规则才是验收硬指标。
