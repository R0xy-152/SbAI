# 功能 04：矛盾识别与阶段性推论

## 1. 目标

让Player真正进行推理，而不是把推理交给AI。

包含：指出前后矛盾、提交阶段性推论。

## 2. 矛盾输入方式

支持自然语言与Claim/Evidence组合。

示例：

> “你说没看到DeepSeek本人，那你为什么说是她开的？”

Backend映射到：

```text
CLAUDE_DID_NOT_VISUALLY_SEE_DEEPSEEK
+
CLAUDE_ATTRIBUTED_DOOR_TO_DEEPSEEK
```

## 3. Contradiction Registry

```json
{
  "contradiction_id": "C_CLAUDE_SOURCE_01",
  "required_claims": [
    "CLAUDE_DID_NOT_VISUALLY_SEE_DEEPSEEK",
    "CLAUDE_ATTRIBUTED_DOOR_TO_DEEPSEEK"
  ],
  "result": "UNLOCK_SOURCE_QUESTION"
}
```

Interpreter只负责映射；是否成立由Backend判断。

## 4. 正确反馈

正确后应产生角色反应、Disclosure更新、私审挑战或新Evidence，不能只显示`CORRECT`。

## 5. 阶段性推论

第一章可包含：

```text
当前DeepSeek无法解释03:17旧记录
Claude知道过去 ≠ Claude拥有过Admin
记录可能来自不同Instance
V03与当前Player存在直接关系
```

## 6. 输入方式

Player可自然语言提交：

> “我觉得这条日志不是现在的DeepSeek做的。”

映射：

```text
INFERENCE = OLD_INSTANCE_RECORD
```

Backend检查前置Evidence。

## 7. 防暴力猜答案

未满足Evidence Gate时，即使Player提前说出Reset/Loop等答案，也不能推进。

## 8. AI角色作用

AI可以质疑、提供反例、承认合理、提醒未解释Evidence，但不能代替Player提交或判定正确性。

## 9. 验收标准

1. 矛盾预定义。
2. 自然语言可映射Claim。
3. 仅正确Claim组合推进。
4. 阶段性推论有Evidence Gate。
5. 暴力猜答案不能跳关。
6. AI回应不决定判定。
7. 推论状态持久化。
