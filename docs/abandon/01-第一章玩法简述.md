# 第一章玩法简述

## 1. 文档目的

本文档用于说明第一章第一小节的核心玩法、玩家目标、主要交互方式、AI参与方式、状态推进和完成条件。

本文档不描述 ACCS 内部实现细节，也不展开完整对白。

---

## 2. 小节目标

玩家与 DeepSeek 在封闭房间中醒来。

玩家需要通过：

1. 与 DeepSeek 沟通获得基础信息；
2. 自由调查房间；
3. 操作 Terminal 并遭遇权限拒绝；
4. 通过纸张压痕获得日志访问密钥；
5. 在控制台输入日志密钥，读取 ACCS 审计日志；
6. 从日志中发现门禁系统存在异常行为；
7. 与 DeepSeek 共同分析 Bug；
8. 由玩家提出漏洞利用思路；
9. DeepSeek 执行玩家无法完成的请求修改；
10. 利用 ACCS Bug 获得门禁权限并离开。

完成后进入下一小节。

---

## 3. 核心玩法循环

```text
沟通获得基础信息
        ↓
自由调查
        ↓
获得静态线索
        ↓
发现系统异常
        ↓
与 AI 共同分析
        ↓
玩家提出 Bug 假设
        ↓
AI 执行玩家无法完成的系统操作
        ↓
Terminal 确定性验证
        ↓
解锁新区域 / 新剧情
```

核心原则：

> 玩家负责观察、判断和提出解决方案；DeepSeek 负责执行玩家无法直接完成的系统级操作；最终是否成功由确定性游戏逻辑判断。

DeepSeek 不能直接读取谜题答案，也不能在玩家尚未获得必要信息时主动公布 Bug 原理。

---

## 4. 玩家与 DeepSeek 的能力差

### Player

玩家可以：

- 观察房间；
- 调查物体；
- 使用鼠标进行铅笔涂画；
- 操作 Terminal；
- 操作维护控制台；
- 阅读日志；
- 与 DeepSeek 自由对话；
- 提出假设；
- 决定如何利用 Bug。

玩家不能：

- 修改 Terminal 实际发送的内部请求；
- 绕过 ACCS Backend 的确定性校验；
- 直接修改 Game State。

### DeepSeek

DeepSeek：

- 无法直接看到房间；
- 不自动获得玩家未描述或未发现的视觉线索；
- 可以理解玩家提供的信息；
- 可以解释基础技术概念；
- 可以在满足剧情条件后访问 ACCS 的“请求修改能力”；
- 可以根据玩家明确提出的方案修改一次待发送请求；
- 不能自行决定门禁最终是否放行。

---

## 5. 第一小节线索结构

### 线索 1：Terminal

玩家可以随时操作。

正常请求结果：

```text
ACCESS DENIED
权限不足
```

作用：

- 明确当前目标：需要打开出口；
- 建立“当前身份没有权限”的问题；
- 不直接告诉玩家如何获得权限。

### 线索 2：纸张压痕

房间中存在遗留下来的纸条。

玩家使用鼠标模拟铅笔侧锋涂画后，逐渐显现上一张纸留下的压痕。

最终获得：

```text
LOG ACCESS
114514
```

作用：

- 提供维护控制台日志密钥；
- 引入一个非对话、可交互的物理谜题；
- 密钥不是门禁密码，避免“找到密码直接开门”。

### 线索 3：维护控制台

玩家输入日志密钥后解锁：

```text
AUDIT LOG
```

作用：

- 提供 ACCS 历史行为记录；
- 第一次正式引入“日志”概念；
- 让玩家从系统行为而非文本说明中发现 Bug。

### 线索 4：ACCS 审计日志

日志必须表现出明确矛盾：

```text
访客 V03 请求打开 EXIT_GATE_01
→ DENY

随后存在一次：
ACTOR_CONTEXT = NOT AVAILABLE
TARGET = EXIT_GATE_01
ACTION = OPEN
→ ALLOW
SOURCE = AUTH_CACHE
```

此前还存在：

```text
维护主体 M17
TARGET = EXIT_GATE_01
ACTION = OPEN
→ ALLOW
CACHE WRITE
```

玩家需要从这些记录中推理：

> 身份缺失的请求错误复用了之前缓存的“允许开门”结果。

---

## 6. 推理阶段

推荐玩家形成以下阶段性认知：

### 阶段 A：发现异常

玩家注意到：

> 同一扇门，已知访客请求被拒绝；未知身份请求却成功。

正确方向反馈：

DeepSeek 可以确认这是有效矛盾，但不能直接解释原因。

### 阶段 B：发现缓存

玩家注意到：

```text
SOURCE = AUTH_CACHE
```

DeepSeek允许解释：

> Cache 是系统为了避免重复计算而临时保存的结果。

此时仍不能直接告诉玩家最终漏洞。

### 阶段 C：发现主体绑定缺失

结合：

```text
M17 → ALLOW → CACHE WRITE
```

和：

```text
ACTOR_CONTEXT = NOT AVAILABLE
→ AUTH_CACHE
→ ALLOW
```

玩家应推理：

> 系统查缓存时没有确认“这个授权属于谁”。

阶段完成后，Game State 记录：

```text
FACT_DISCOVERED:
AUTH_CACHE_NOT_BOUND_TO_ACTOR
```

### 阶段 D：提出利用方案

玩家需要主动提出等价方案，例如：

- “能不能让这次请求不带身份？”
- “能不能模拟日志里那个身份缺失的请求？”
- “把我的访客身份从请求里拿掉试试。”

此时 DeepSeek 才可以执行 Request Patch。

---

## 7. AI 不可替代交互

第一小节必须包含一次“玩家知道怎么做，但自己做不到”的合作动作。

正常 Terminal 请求：

```text
actor: PLAYER
role: GUEST
target: EXIT_GATE_01
action: OPEN
```

玩家无法通过 UI 删除 `actor` / `role`。

DeepSeek 在获得玩家明确授权和正确推理后，可以生成一个 `action_proposal`：

```text
PATCH_ACCESS_REQUEST
```

Game Orchestrator 校验前置条件后，创建游戏内虚构请求：

```text
actor_context: MISSING
target: EXIT_GATE_01
action: OPEN
```

由 ACCS 确定性执行。

---

## 8. 引导设计

引导必须用于避免停滞，不能直接泄露答案。

### 引导 1：玩家长期不调查

触发：

- 连续自由对话若干轮；
- 尚未调查出口。

DeepSeek：

> “继续聊天我倒是不介意，不过我们是不是至少先看看出口？”

### 引导 2：拿到日志密钥但不知道用途

DeepSeek只可提示：

> “这串东西看起来不像门锁密码，更像某种访问凭证。”

不能直接说“去控制台输入”。

### 引导 3：读取日志后没发现矛盾

DeepSeek：

> “先别急着看那些术语。比较一下，同一扇门的几次结果是不是完全一致。”

### 引导 4：发现异常但不知道 Cache

DeepSeek：

> “那次成功不是来自正常权限判断。日志里写了它从哪里拿到结果。”

### 引导 5：已理解 Bug 但不会利用

DeepSeek：

> “正常界面会强制带上你的身份。问题是，我们是不是一定得让它带上？”

---

## 9. 小阶段奖励

### 奖励 A：发现压痕

- 纸张视觉发生明显变化；
- 解锁日志密钥；
- 可加入短音效。

### 奖励 B：成功解锁 Audit Log

- 控制台 UI 从 LOCKED 切换为 AUDIT LOG；
- DeepSeek认可玩家找到了一条真正有用的线索。

### 奖励 C：发现“未知身份请求却 ALLOW”

- DeepSeek明确确认“这是一条异常”；
- Game State 记录 `FOUND_AUTH_ANOMALY`。

### 奖励 D：推出缓存主体绑定 Bug

- DeepSeek第一次明确认可玩家推理正确；
- Game State 记录 `AUTH_CACHE_NOT_BOUND_TO_ACTOR`；
- 解锁 DeepSeek 的 Request Patch 能力。

### 奖励 E：漏洞利用成功

Terminal：

```text
ACCESS GRANTED
```

- 门锁机械音；
- 门体开启；
- 小节完成；
- 进入下一剧情阶段。

---

## 10. 固定剧情与 AI 边界

### 必须由固定系统控制

- 房间中的所有客观线索；
- 纸张压痕内容；
- 日志密钥；
- ACCS 日志内容；
- Bug 真实原理；
- 请求执行结果；
- Game State 更新；
- 门是否打开；
- 小节结束事件。

### 可以由 AI 生成

- DeepSeek 对玩家问题的自然回应；
- 技术概念的角色化解释；
- 对错误假设的讨论；
- 对正确中间推理的自然反馈；
- 吐槽、情绪、性格表现。

### AI 禁止行为

- 在未发现日志前公布 Bug；
- 直接给出最终利用方法；
- 自行修改请求；
- 自行决定 ACCESS GRANTED；
- 根据隐藏 Ground Truth 纠正玩家尚未掌握的信息。

---

## 11. 完成条件

第一小节完成必须同时满足：

```text
FOUND_TERMINAL = true
FOUND_LOG_KEY = true
AUDIT_LOG_UNLOCKED = true
FOUND_AUTH_ANOMALY = true
AUTH_CACHE_NOT_BOUND_TO_ACTOR = true
PLAYER_PROPOSED_EXPLOIT = true
PATCH_REQUEST_EXECUTED = true
EXIT_GATE_OPEN = true
```

允许玩家以不同顺序发现 Terminal、纸张和维护控制台，但最终漏洞利用必须建立在已发现 Bug 的状态上。
