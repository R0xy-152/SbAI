# 第一章第一小节剧本：《异常授权》

## 1. 文档目的

本文档为开发可执行剧本。

标记说明：

- **[FIXED]**：固定剧本 / 固定系统行为；
- **[AI]**：允许 Character Runtime 自由生成；
- **[AI-GUIDED]**：允许 AI 生成，但必须遵守当前事实与禁止信息；
- **[SYSTEM]**：确定性 Game State / Puzzle / ACCS 行为；
- **[HINT]**：防卡引导；
- **[REWARD]**：阶段正确反馈。

# 13. 第一阶段推理：发现矛盾

玩家应注意：

```text
V03 / GUEST / OPEN
→ DENY

UNKNOWN ACTOR / OPEN
→ ALLOW
```

### 正确表达示例

- “为什么不知道是谁反而能开门？”
- “同一扇门为什么前一次拒绝，后一条却通过？”
- “这次成功请求连身份都没有。”

不要求关键词完全一致。

# 17. 第三阶段：发现真正Bug

玩家还需要意识到：

> Cache Key 没有区分是谁申请。

日志暴露：

```text
CACHE WRITE:
EXIT_GATE_01 / OPEN / ALLOW
```

这里没有：

```text
M17
```

玩家可能问：

> “它缓存的时候为什么没有写M17？”

或：

> “这条缓存到底是谁的？”

或：

> “是不是只记了门和操作，没记是谁？”

---

## [SYSTEM]

Narrative Interpreter识别：

```text
SIG_CACHE_SUBJECT_BINDING_MISSING
```

设置：

```text
auth_cache_not_bound_to_actor = true
EV_CH1_CACHE_BUG_UNDERSTOOD
```

---

## [REWARD]

DeepSeek第一次明确确认核心推理：

> “……对。”

> “不是你获得了M17的权限。”

> “是这套东西压根没确认——那条允许开门的结果属于谁。”

> “它只记得：这扇门，上一次有人申请打开的时候，可以。”

这是本小节主要推理高潮。

可加入：

- UI轻微音效；
- 日志中 `CACHE WRITE` 行高亮；
- 解锁新的对话能力说明。

## 25. 第一小节隐藏伏笔

以下信息存在于开发 Ground Truth，但本小节不得向玩家解释：

```text
1. Audit Log 中部分记录并非第一次发生。
2. Player 与 DeepSeek 此前可能经历过相似流程。
3. Sandbox 存在异常恢复 / Reset 机制。
4. 外部 Supervisor 的日志不一定随 Sandbox 一起恢复。
5. 当前 Bug 是否为自然缺陷尚未确认。
6. 某个外部角色可能知道或利用该缺陷。
```

这些内容只作为后续章节伏笔。

---

## 26. 剧本验收标准

1. 玩家不与DeepSeek交互时，不能完成最终Request Patch。
2. DeepSeek不能在玩家未发现日志前公布Bug。
3. 纸张、Terminal、维护控制台允许不同调查顺序。
4. 日志密钥不能直接用于门禁。
5. 日志必须能独立表现出“已知访客DENY / 未知身份ALLOW”的明显矛盾。
6. 玩家必须主动形成“缓存没有绑定身份”的核心推理。
7. 玩家必须主动提出利用方案。
8. DeepSeek只执行玩家提出的方案。
9. ACCS最终结果由确定性系统产生。
10. 门打开后才进入下一小节。
