# 11 — 第一章调查主线落地说明

## 0. 文档定位

本文档用于指导 `docs/10-第一章调查内容配置.md` 如何接入实际可玩运行时。

本文档不重新定义第一章剧情真相，不修改 Evidence / Claim / Contradiction / Inference 内容。

职责区分：

```text
docs/10
回答：第一章具体发生什么？

docs/11
回答：这些内容按什么顺序接进游戏？
```

本文档只规定：

- 当前阶段目标；
- 落地顺序；
- 前后端需要具备的能力；
- 每个小闭环的完成条件；
- 本阶段禁止提前开发的内容；
- 阶段验收标准。

不规定具体类名、目录结构、API路径、数据库表结构或前端组件实现方式。开发实现应优先适配现有架构。

---

# 1. 本阶段目标

将第一章调查内容从“数据定义与门控存在”推进到“Player能够通过正常游戏操作完整玩通调查主线”。

本阶段起点：

```text
03:17事件即将发生
```

本阶段终点：

```text
Player完成 INF03_V03_IS_PREVIOUS_PLAYER_INSTANCE
↓
SANDBOX INTEGRITY FAILURE
↓
进入Recovery入口
```

本阶段**不实现Recovery小游戏本体**。


因此本阶段核心任务是：

> **建立完整的可玩解锁链。**

# 6. Phase B — Claude调查闭环

这是本阶段第一个必须独立验收的完整玩法闭环：

```text

↓

↓

↓
指出矛盾
↓

↓

↓

↓

```

## 6.1 Claude公开Claim

Player通过询问与Evidence出示，应能够获得：

```text
CL_CLAUDE_01
CL_CLAUDE_02
```

核心信息：

```text
Claude：门是DeepSeek打开的。
Claude：我没有看到DeepSeek本人。
```

## 6.2 CT01

Player通过自然语言指出或Claim / Evidence交互确认：

```text

```

```text
CT01 = confirmed
↓
解锁Claude Private Interview Challenge
```

不能直接自动进入私审。

## 6.3 Claude私审

成功进入Private Interview后，必须稳定获得：

```text

CL_CLAUDE_04
```

```text

```

可进一步获得：

```text

EV07_CLAUDE_RECOVERY_ACCESS
```

## 6.4 INF01

```text

```

后，应允许提交：

```text

```

```text

↓
```

# 7. Phase C — ChatGPT出现与第一次Evidence整理

GPT应在Claude调查取得足够进展后出现，不要在开场就让GPT在线。

目标体验：

> GPT出现时，Player应该明显感觉“终于来了一个会整理事情的人”。

## 7.1 GPT Availability

触发条件应与调查进度绑定，例如语义上：

```text
Claude信息来源已确认存在缺口
+
03:17基础Evidence已获得
```

具体实现由现有Narrative Runtime决定。

## 7.2 EV10

GPT出现后，应通过系统记录或对话事件生成：

```text
EV10_GPT_FIRST_SUMMARY
```

该Evidence不是客观日志，而是GPT的调查整理结果，因此必须标注来源为GPT。

## 7.3 第一次Summary目标

GPT此时应：

- 帮Player降低信息负担；
- 给出合理调查优先级；
- 让Claude显得更值得调查；
- 不表现明显恶意；
- 不提前暴露选择性Evidence排序机制。

本阶段玩家应该觉得：

> GPT很有用。

# 8. Phase D — 豆包出现与Observation / Interpretation闭环

豆包在GPT之后出现。

目标：

> 第一次明确教会Player：角色说的话不一定等于角色真正观察到的事实。

## 8.1 豆包公开Claim

需要获得：

```text
CL_DB_01
```

例如：

> “GPT早就在这里了。”

GPT则坚持当前角色Instance是刚刚才出现，形成表面冲突。

## 8.2 私审挑战

Player需要通过小游戏区分：

```text
Observed Fact
vs
Interpretation
```

正确拆解：

```text
Observed:
屏幕显示GPT相关文字

Interpretation:
GPT本人早已在场
```

## 8.3 私审结果

成功后：

```text
PRIVATE_INTERVIEW_DOUBAO = unlocked
```

并获得：

```text
CL_DB_02
CL_DB_03
EV08_GPT_RECOVERY_SERVICE
```

结果应让Player理解：

> 豆包没有撒谎，但她的结论不能直接当事实。

Claude与豆包调查完成后，应确保Player能够回到03:17执行者问题。

核心Evidence：

```text

EV05_ARCHIVED_ACTOR_FRAGMENT
```


- 当前DeepSeek主要嫌疑解除；
- DeepSeek可产生角色化回应；
- 不进入悲情或信任崩塌；
- 保持伙伴关系。

# 17. AI职责

LLM只负责：

```text
理解Player自然语言
映射Intent / Claim / Topic
按角色人格表达
基于允许Facts回应
在允许范围内追问与解释
```

LLM不得：

```text
生成新的Evidence
改变Evidence内容
决定Contradiction正确性
决定Inference正确性
自行开放Private Interview
自行修改Narrative Phase
提前透露Ground Truth
```

---

# 18. Character Context要求

每个角色只能获得自己有权知道的信息。

核心：

```text
Global Ground Truth
≠
Character Context
```

重点验证：

- DeepSeek不能因为Backend知道DEEPSEEK#03，就自动知道旧Instance经历；
- Claude可以知道过去的一部分，但必须受Disclosure State限制；
- GPT可以获得自己允许看到的Evidence，但不能直接读取作者层最终真相；
- 豆包必须区分Observed Fact与Interpretation。
