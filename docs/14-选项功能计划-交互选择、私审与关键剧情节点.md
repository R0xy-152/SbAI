## 2. 设计

### 2.1 后端「可用选项」生成器

- 新增 backend/app/game/options.py：纯函数 build_options(state)，按 Narrative State 生成**当前合法**的选项（D3：未解锁不下发）。
- 选项模型：{ id, label, kind, payload, hint? }，kind ∈ chat_routing / investigate / evidence_present / deduction / private_interview / recovery / narrative。
- payload 是既有执行端点的参数（如 {action, hotspot_id}、{character_id}、{claim_ids, evidence_ids}），前端不解释其含义、只回传。
- 下发通道：扩展 GET /api/game/state 的 options 字段（前端 reconcileStage 已在对账后拉取；旧前端忽略新字段，无回归）。
- 引导式推理选项（D2）：kind=deduction 的选项点击后只展示提示行（系统台词「……或许可以质疑：××」），玩家自由输入推理原文，判定仍走 /api/game/deduction。

### 2.2 前端 OptionsPanel

- 位置：对话框上方（GameView 内，z-20）；形态：气泡按钮条（D6），短选项直接渲染，需要上下文的小面板（私审挑战选择等）在点击后弹出。
- 生命周期：随 reconcileStage 的 state.options 对账（出现/消失全部后端权威）；点击 → 调对应执行端点（或按 kind 走本地提示展示），执行后重新对账。

### 2.3 选项接入清单（按主线推进）

| 阶段 | 选项 | kind | 触发条件（后端判断） |
|---|---|---|---|
| 开场 | 调查桌上的纸（含拓印） | investigate | CH1_NOTE_01 未完成（迁移现有按钮） |
| Claude 登场后 | 调查 C-02 隔离门 / 角色注册表 / 终端 | investigate | 对应 hotspot 可用且未完成 |
| Claude 登场后 | 找 Claude 谈谈 / 找 DeepSeek 谈谈 | chat_routing | 对应角色在 available_characters |
| 出示解锁后 | 对在场角色出示证据 ×N | evidence_present | FIRST_IMPOSSIBLE_EVENT_RESOLVED + 证据已获得 + 角色在场 |
| 证词期 | 质疑 Claude 的说辞（CT01）/ 质疑 GPT 的摘要（CT04） | deduction（提示） | 对应 claim 已入 store 且矛盾未解决 |
| 证据期 | 质疑 DeepSeek 与 03:17 的关系（INF01）/ V03 与当前玩家的关系（INF03）等 | deduction（提示） | 对应 INFERENCE_GATES 证据已集齐且推理未接受 |
| 私审期 | 与 Claude / ChatGPT / 豆包对质（挑战选项） | private_interview | 对应 private_interview_challenges 为 true |
| 收尾 | SANDBOX INTEGRITY FAILURE → Recovery 抉择（委托/删除等） | recovery | chapter1.phase == recovery_required |
| 结局 | 安全审查 / Bad End 分支 | narrative | 对应阶段 |
