## 1. 一句话定位

**一个「语言自由、事实不自由」的 AI-native 悬疑 Galgame：玩家唯一交互是自然语言对话，前端只做表现，剧情与状态由后端确定性叙事运行时权威决定，LLM 输出经三层校验后才可呈现。**

上线运行中：https://sbai.xin/（序章固定剧本 + DeepSeek 真机 AI 后日谈，邀请码账号体系，备案 + HTTPS）。

## 2. 用户问题与需求定义（PRD 摘要）

| 问题 | 需求定义 |
|---|---|
| LLM 自由对话会编造剧情/越权/说人设外的话 | 三层校验：Structured Response（schema）→ Character/Narrative Validation（权限与事实边界）→ Semantic Consistency（防御纵深）；被拒即安全回落 |
| 剧情推进依赖模型自觉会崩 | 确定性叙事运行时：Signal → Event → Requirements → Commit，主线事件 once + 幂等；AI 只负责语言表达 |
| 角色信息隔离（如 DeepSeek「看不见」）不可靠 | 权限边界在 Context 构建层拦截，不是 prompt 请求；违反即 reject（红队 3/3 拦截、0 误伤） |
| 记忆要么记不住要么全都塞 | 确定性检索 + 轻量语义召回 + 衰减/强化；玩家画像与剧情记忆分区（召回 5/10→10/10） |
| 邀请码运营无数据 | 轻量账号 + quota + 开发者留言收集（docs/18/20） |
| 没有真实玩家反馈与运营指标 | 事件埋点 + 漏斗看板 + 反馈分类 Agent + 人工抽检（docs/21） |

## 3. 方案取舍（关键决策记录）

1. **前端只做表现**：不持有 Game Truth，只消费后端下发的确定性结果——可解释、可测试、可回滚。
2. **LLM 不可信是设计前提**：所有生成内容走校验再 Present，LLM 不能直接改 Game State/前端/数据库。
3. **不引入 RAG/向量库**：当前规模用确定性检索 + 轻量语义召回足够（AGENTS.md 硬规则），避免为关键词堆架构。
4. **固定剧本 + AI 后日谈分层**：先保证可上线可体验（docs/17/19），AI 在受控边界内发挥。
5. **验证文化**：每个任务必须有 `validation-results/<任务>/result.md`，状态分 PASS/PASS_WITH_LIMITATION/FAIL/BLOCKED，失败实验同样留档。
6. **成本意识**：反思回灌、一致性评审默认关（额外 LLM 调用按需开启），每回合 token 用量与成本可测（docs/21 §3）。

## 4. 指标体系（docs/21 §2 事件字典）

- 漏斗：开始序章 → 访问选择 → 角色篇完成 ×3 → 序章完成 → 进入 AI 对话（每会话最远阶段 → 流失节点）
- 角色偏好：首访分布 / 聊天角色选择分布
- AI 质量：请求成功率、延迟 P50/P95、单次完整体验成本、校验拦截数（按门分布）
- 反馈：留言主题/严重度分布、去重组、分类 Precision（人工抽检，n 如实标注）

## 5. 实验与评测

| 实验 | 结论 | 证据 |
|---|---|---|
| LLM-as-judge 回归（8 用例 × 4 维） | persona 0.81 / repetition 0.85 / no_leak 0.86 / anti_template 0.88（单次跑分，量级参考） | eval-live-deepseek |
| 三臂 A/B v1（裸/管线/反思） | 单次 8 用例噪声（同臂两次基线差 0.15）≥ 臂间分差：**不能断言管线更好或更差**；可断言「加确定性强约束不损失质量」+ 门禁真机实执行 | eval-ab |
| 三臂 A/B v2（32 用例 × 2 重复，n=64/臂） | 全部分差 < 噪声（pooled std 0.27–0.34），三臂同档；评审噪声量化（同臂重复平均差 0.25）；管线附加成本可量化（生成延迟 +50%、token +21%）；红队 3/3 + 0/3 跨版本复现 | eval-ab-v2 |
| 一致性校验器红队 | 越界 3/3 拦截、干净对照 0 误伤（确定性输入的强证据） | eval-ab |
| 记忆召回（合成） | 语义召回 50%→100%；端到端引用 3/4（第 4 例上下文已含、模型未用→模型利用层问题） | eval-memory-recall |
| 记忆写入（真实数据回放） | 126 条真实消息仅 4 条提案（3.2%）→ 写入层瓶颈；few-shot 引导后仍 3.2%（逐存档一致），提示词路线关闭 | eval-memory-recall-realdata / memory-write-fewshot |

## 6. 失败与迭代（诚实记录）

1. **生产零记忆**：线上 0 条记忆不是持久化 bug，而是模型不主动提案（3.2%）。定位方法：真实数据回放 + 逐层归因（写入 vs 检索）。当前口径：检索层就绪、写入机制待验证。
2. **few-shot 无效**：强化提示词后提案率 3.2%→3.2%，果断关闭路线 B；未来若真实反馈证明记忆重要，走确定性抽取器路线（先建标注集再测 Precision/Recall）。
3. **A/B 不可断言**：发现单次小样本噪声大于分差，主动把报告口径改为「未证实/未证伪」而不是包装成胜利。
4. **分区缺陷**：画像溢出窗口后不参与强化（实验意外发现）→ 分区不变量修复 + 回归测试（memory-partition-fix）。
5. **迭代纪律**：每次真机部署前先跑本地 588 测试 + 容器内回放验证，生产从未因新功能停机。

## 9. 面试口径边界（能讲 / 不能讲）

- **能讲**：架构决策与理由；三层校验与红队数字（3/3、0/3）；记忆召回 50%→100%；3.2% 提案率与 few-shot 失败→路线关闭的判断过程；A/B 噪声分析（体现「知道什么不可信」）；558→588 测试与证据链纪律。
- **谨慎讲**：真机 4 维分数是单次小样本（量级参考）；漏斗/分位数在样本 <50 时只是管线演示；成本是占位价格口径（token 已落库可重算）。
- **不能讲**：把确定性状态机包装成 Agent；把 A/B 分差说成提升；声称记忆系统生产可用（写入层待验证）。
