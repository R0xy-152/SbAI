# 功能 01：调查场景热点

## 1. 目标

让 Player 主动探索封闭环境并获得可用于后续审问与推理的客观信息。

该功能只负责：

> **环境交互 → 发现事实 / 证据**

不负责角色回答、不负责推理判定。

## 2. 玩家行为

Player 可以：

- 点击场景热点
- 查看热点细节
- 对部分热点执行简单交互
- 重复查看已调查热点

第一章首个固定交互：

```text
空白纸 + 铅笔
↓
鼠标涂画
↓
显现隐藏文字
```

纸条建议内容：

```text
03:17

不要把管理员权限交给
“最会替你解释的人”。

—— V03
```

具体文案可在剧本阶段调整，但 `03:17` 与 `V03` 属于重要真相锚点。

## 3. Hotspot 数据结构

```json
{
  "hotspot_id": "CH1_NOTE_01",
  "scene_id": "ROOM_A",
  "state": "hidden",
  "interaction_type": "paper_rubbing",
  "repeatable": true,
  "evidence_on_complete": "EV_NOTE_V03"
}
```

`state` 只允许：`hidden / visible / investigated / completed`。

## 4. 纸张涂画

Frontend：鼠标拖动累计Mask，达到覆盖阈值后自动完成，不要求精确涂满。

Backend只接受：

```text
PAPER_RUBBING_COMPLETE
```

并设置：

```text
hotspot.CH1_NOTE_01 = completed
evidence.EV_NOTE_V03 = acquired
```

Frontend不得自行生成Evidence。

## 5. 其他热点类型

MVP支持：`inspect / click / paper_rubbing / open_close`。

禁止第一章为每个热点单独实现全新交互系统。

## 6. 调查结果

调查热点只能产生：Evidence、Scene Fact、Visual State Change、Narrative Event。

示例：

```text
调查Terminal → 获得“03:17存在Admin Session”
调查Claude房间 → 获得“房门在03:17释放”
调查系统身份栏 → 后期发现 CURRENT SUBJECT = PLAYER_V04
```

## 7. 防卡

若Player长时间无进展，DeepSeek可自然提示未调查区域，但默认不直接点名具体热点。

## 8. 验收标准

1. Hotspot状态由Backend持久化。
2. Refresh后状态不丢失。
3. 纸张涂画完成后只获得一次Evidence。
4. 重复调查不会重复触发副作用。
5. DeepSeek看不见的视觉信息不会自动进入其Context。
6. 调查结果可以被证据系统引用。
7. Hotspot交互不依赖LLM。
