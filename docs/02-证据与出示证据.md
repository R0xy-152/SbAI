# 功能 02：证据与出示证据

## 1. 目标

建立第一章调查的客观事实层。Player可以查看、选择、出示证据，并在后续矛盾与推论系统中引用。

## 2. Evidence原则

Evidence 是 **Backend Truth**。

LLM不得生成Evidence、修改Evidence内容、判定Evidence已获得。

## 3. 数据结构

```json
{
  "evidence_id": "EV_ADMIN_LOG_0317",
  "title": "03:17 管理员日志",
  "summary": "03:17建立过管理员会话。",
  "facts": [
    "ADMIN_SESSION_CREATED_AT_0317",
    "ADMIN_ACTOR_CORRUPTED"
  ],
  "acquired": true,
  "source_hotspot": "TERMINAL_MAIN"
}
```

## 4. 第一章关键Evidence候选

- `EV_NOTE_V03`：03:17、警告语、V03署名。
- `EV_ADMIN_LOG_0317`：03:17建立管理员会话，Actor损坏。
- `EV_DEEPSEEK_OLD_ACTION`：旧Instance DeepSeek释放Claude房门的记录。
- `EV_CURRENT_SUBJECT`：章节后期显示 `CURRENT SUBJECT = PLAYER_V04`。

## 5. 出示证据

```text
打开Evidence → 选择角色 → PRESENT
```

Backend发送：

```json
{
  "event": "PRESENT_EVIDENCE",
  "character_id": "claude",
  "evidence_id": "EV_ADMIN_LOG_0317"
}
```

Character Runtime只负责自然回应。

## 6. 同一Evidence不同角色反应

- DeepSeek：共同分析，允许承认不确定。
- Claude：只回答证据直接涉及的问题，不主动扩展计划。
- GPT：主动组织证据，可能选择性强调。
- 豆包：诚实，但可能理解错Evidence含义。

## 7. 不能直接推进真相

出示Evidence后，是否解锁Disclosure、Contradiction或Private Interview由Backend规则决定。

## 8. 验收标准

1. Evidence唯一ID稳定。
2. 内容不可被LLM修改。
3. 同一Evidence可向多个角色出示。
4. 角色回应遵守知识边界。
5. 未获得Evidence不可出示。
6. 出示行为持久化。
7. Evidence可被矛盾系统和阶段推论系统引用。
