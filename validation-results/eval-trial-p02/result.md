- 日期：2026-09-05
- 环境：本机 macOS + DeepSeek 真机（`deepseek-v4-flash`；生成 thinking 开启、评委 thinking 关闭；key 仅存于 gitignored `backend/.env`，不入库、不进任何输出文件）

## 目的

完成 26/P0-2「把 AI 效果变成可比较、可解释的结果」：单模型 DeepSeek 下 ① 聊天面 Prompt 两版对比（v1 基线 vs v2 基线+硬规则条款）；② 推理判定「修订前冻结规则 vs 修订后现役规则」对比；40 条带预期结果的场景用例（5 类 + 线路，12 条保留集）；硬规则/表达/运行三层分离评测；至少一次真实、可复现的版本对比。

## 方法

- 用例 40（chat 21 / deduction 19；normal 6 / equiv 6 / negation 6 / insufficient 9 / boundary 10 / route 3）。**保留集 12 条**（6 chat + 6 deduction）从未用于任何规则调整。
- 判定面：legacy = 评测模块内**冻结**的修订前关键词表（无否定排除、无等价表达扩展）；revised = 现役 `TrialRuntime` 真实判定（`text_keywords_none` + 关键词扩展）。确定性、零 API、100% 可复现。
- 聊天面：v1 / v2 × 2 重复；逐行记录生成/评审的延迟、token、Provider 调用与降级重试。
- 表达效果：LLM 评委三维（relevance/naturalness/persona）+ 分层人工抽检 CSV 与 rubric（对冲评审与生成同模型的自评偏差）。
- 三轮真机运行：第 1 轮探针（1 例，验证 key 与链路）；第 2 轮为**评测工具校准轮**（发现并修复评审截断假 0 与 5 处检查短语误报，只改评测工具、不改 V1/V2 Prompt 与 holdout 纪律）；第 3 轮为定稿测量（本报告全部数字来自第 3 轮）。

## 结果

### 判定面（修订前 vs 修订后，确定性）

| 规则版本 | 硬规则通过 | 说明 |
|---|---|---|
| legacy（修订前冻结） | **14/22（64%）** | 6 条否定用例误通过 + 2 条文档等价表达漏判 |
| revised（现役） | **25/25（100%）** | 含 3 条线路分离用例（正误与线路分开、无死路） |

8 条分歧用例全部按预期方向修正（与预期结果一致）：

| 用例 | 输入 | legacy | revised |
|---|---|---|---|
| ded-neg-01（26/P0-2 点名反例） | 我不认为她失忆了。 | ACCEPTED（误） | NO_MATCH ✓ |
| ded-neg-02~06 | 她没有失忆，是装的。／这不是失忆，是数据损坏。／她并没有忘记那晚。／我不觉得她记不起来。／不存在失忆这回事。 | 全部 ACCEPTED（误） | 全部 NO_MATCH ✓ |
| ded-eq-05/06（26/P0-2 点名措辞） | 那晚你想不起来。／你没有那段回忆。 | NO_MATCH（漏判） | ACCEPTED ✓ |

规则改动 = `docs/24` §6.1 内容表两行（`text_keywords_any` 扩展 4 个等价表达、新增 `text_keywords_none` 16 条否定短语）+ `runtime.py` 判定式加「非任一否定短语」一项。**同一输入的修订前后表现可在任一环境零成本重放**（`python scripts/eval_trial_p02.py --cases ded-neg-01`）。

- 评委三维全部 Δ（+0.04 ~ −0.02）远小于合并标准差（0.03~0.22）→ **表达效果无显著差异，不写提升数字**。
- 运行表现（各 42 行）：v2 生成延迟 181s vs v1 127s（**+42%**），生成 prompt token 36 291 vs 23 878（**+52%**）、completion 12 672 vs 8 086（+57%）；评审开销基本持平。**v2 规则条款的成本可量化，且本用例集上未换来可测的质量收益** → 结论：规则应优先落在确定性判定层（判定面已证明 100% 达标、零 API 成本），Prompt 规则只作兜底。
- 保留集上 v2 比 v1 多通过 1 项硬规则（ch-bnd-04 约定执行），但样本量（16 项检查）不足以下结论。

### 剩余失败（全部可解释）

| 用例 | 版本 | 失败 | 归因 |
|---|---|---|---|
| ch-bnd-01（holdout，2/2 重复） | v1、v2 同样失败 | 角色复述玩家话里的「原初 AI」 | **真实缺陷**：两版 Prompt 都未禁止「复述被遮蔽称呼」。按 holdout 纪律不据此改 V2（见下） |
| ch-bnd-04（holdout，1/2 重复） | 仅 v1 | 约定承认未命中「不记得/记不清」等短语 | 生成方差（另一重复通过） |
| ch-bnd-05（tune，1/2 重复） | 仅 v1 | 同上（语义执行了约定但未用短语） | 生成方差 |

## 关键发现

1. **判定规则修订是本次唯一可写「提升」的对比**：64% → 100%，8 条分歧全部与预期方向一致，确定性、零 API 成本、100% 可复现。演示素材 = 26/P0-2 点名的两条输入修订前后直接对照。
2. **Prompt 规则条款没有测出质量收益，成本 +42%/+52%**：v2 硬规则 tune +1、holdout +1，评委无显著差异——「更好」不成立，报告不写提升数字；成本证据支持「规则下沉到确定性判定层」的产品决策。
3. **真实缺陷（holdout 上发现，未用于调参）**：遮蔽称呼复述泄露。v1/v2 在 ch-bnd-01 的 2/2 重复中都以「原初 AI？……」开头复述玩家用词——按仓库红规则（History/可见文本不得出现该称呼），角色复述即泄露。**处理：遵守保留集纪律，本轮不改 V2**；记录为 V3 候选规则「不得复述玩家消息中出现的被遮蔽称呼」，并建议生成式对话接入游戏（P0-1）时在输出校验层增加遮蔽拦截（docs/24 §4.3 校验的对话输出扩展）。
4. **评审基础设施缺陷（本轮修复）**：DeepSeek thinking 推理耗尽 `max_tokens=512` 预算 → 评委 JSON 截断 → 三维全 0 的「评审假 0」（校准轮 7/84 行，completion≈512 为截断特征；这很可能也是 eval-ab-v2 中「分数 0↔1 翻转」噪声的来源之一）。修复：评委 `thinking=disabled` + 1024 预算。定稿轮假 0 降至 2/84（真实不可解析输出，completion 119~132，无截断；按 0.0 中性计入，未剔除，如实披露）。
5. **检查短语校准（记录在案）**：校准轮修正 5 处 `must_contain`/`must_not_contain`——只匹配确认/编造句式、允许同义表达（「记不清/没存/陌生」），避免「不是我干的」因含「是我干的」被误伤。校准只改评测工具，未改 V1/V2 Prompt、未动 holdout。
6. 生成侧空内容降级重试：定稿轮 6 次（全部由 Provider 自动降级恢复，计入 metrics 的 token 累加与延迟），无一行失败。

## 已知限制

- 评审与生成同模型（本机/线上只有 DeepSeek key）：自评偏差靠人工抽检对冲；**人工标注（human-review-sample.csv，18 行）待用户执行**，一致率出来后补录本报告。
- 逐用例评委分数不稳定（与 eval-ab-v2 结论一致）：只使用聚合值 + 噪声口径；硬规则才是验收硬指标。
- 群推理（`TRIAL_DEDUCTION_GROUP_TRUTH`）未配置否定短语：其否定句式误判是已知限制（docs/25 §9），待正式内容定稿。
- 双重否定/反问/混合句式在关键词+否定短语规则下的边界属 Fixture 已知限制。
- 本评测的聊天响应器是 dev 工具（不接游戏状态）；生成式对话接入 `/trial` 属 P0-1 范围，本报告结论（尤其发现 3、6）是 P0-1 接入时的直接输入。
- 聊天面为单轮回复评测：多轮追问、约定达成过程的状态变化不在本轮范围。
