# ops-iteration-1 — 第一次数据驱动迭代（预注册协议）

> **本文件在体验数据产生前登记**（2026-09-04），先锁口径再收集数据，防止事后挑数字。
> 数据到齐后按 §3 规则执行，结果写入同目录 `result.md`（含前后对比与限制）。

## 1. 背景

docs/21 §7 的迭代协议落地：招募 10-20 名体验玩家（15 个体验邀请码已发放登记），
观察序章漏斗与留言反馈，只改一个问题，前后对比。

## 2. 预注册指标（以 docs/21 §2 事件字典为准）

- 主指标：**序章完成率** = prologue_completed 会话数 / prologue_start 会话数。
- 过程指标：各阶段到达数（visit_chosen / visit_completed / three_visits / ai_chat_entered）、
  每会话最远阶段分布（流失节点）、角色篇完成率（按角色）。
- AI 指标：成功率、P50/P95 延迟、单次完整体验成本（占位价格口径）。
- 反馈指标：主题分布 Top3、严重度 high 条数、分类 Precision（人工抽检，n 如实标注）。

## 3. 决策规则（预注册）

1. 观察窗口：首条事件起 ≥3 天，且 prologue_start ≥ 10（不足则顺延，不提前下结论）。
2. 问题选择：取「最大绝对流失阶段」；若多个阶段流失接近（<2 会话），取留言里被点名的
   具体场景；无留言则取角色篇完成率最低的角色篇。
3. 只改一个变量，改动前记录基线（事件快照 + CLI report 存档到本目录 `baseline.md`）。
4. 改动部署后再观察 ≥2 天（或 ≥8 个新完成会话），计算前后完成率差：
   - 提升 ≥10 个百分点且 n≥10 → 记录为有效改进；
   - 其余如实记录为「未观察到明显变化」，不改口。
5. 输出：`result.md`（基线/改动/后测数据/结论/限制），并据此更新 docs/21 与 README。

## 4. 已知限制（预注册）

- 小样本：完成率差是量级参考，不做显著性检验。
- 无法控制变量：体验者之间、时间段之间可能存在混杂；迭代结论标注为「观察性」。
- 人工抽检集不足 50 条时按实际量全量标注并记录 n。
